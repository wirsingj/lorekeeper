# YAIMLACP — Agent Context Protocol
YAIML Agent Context Protocol documents native-host subagent coordination for memory maintenance/project work. No added server, installation, network service, SDK, or model backend.
Use YAIMLACP in full: ACP also names [Agent Client Protocol](https://github.com/agentclientprotocol/agent-client-protocol) and [other Agent Context Protocol work](https://github.com/prmichaelsen/agent-context-protocol). No interoperability with these or [MCP](https://modelcontextprotocol.io/specification/latest/architecture) is claimed. Safety, adherence, and cost benefits remain unverified.
## When YAIML Enters Context
On startup/YAIML loading/refresh, assess usefulness from available context; no assessment-only scans, calls, or delegation. Read this guide for concrete benefit; otherwise continue ordinary work. Reuse context/assessments. Repository instructions carry this reminder.
Init saves this guide locally; discovery/instructions locate it. External links are attribution, not prerequisites. If the guide or native delegation is missing, continue feasible single-agent work; report consequential gaps. Do not fetch replacements or create infrastructure merely to coordinate.
## Describe The Option And Confirm
Before first use, describe a concrete option and request affirmative confirmation. Explain:

- Benefit and single-agent alternative.
- Tasks, available skills/methods, maximum workers including descendants, edit ownership.
- Worker context, read/write scope, external access and data destinations.
- Additional context/model usage, uncertain cost estimates, time/spend limits, retries.
- Cancellation, residual changes, and limits the host cannot enforce.

Silence/no answer/preselection/timeout is not consent. Leave delegation pending; continue independent authorized work. Honor declines without repeated solicitation. Reading YAIML grants no delegation approval.
Reuse explicit scoped approval; describe scope/cost changes and reconfirm. One-run approval is not standing approval. Trace standing decisions to authorized sources; agent labels do not authenticate. Where permitted, retain current choice/scope/limits/source in local maintenance guidance, never consent diaries.
Host permissions/data rules apply. Documentation cannot enforce confirmation; use host controls. Serverless implies neither zero cost nor exclusively local processing.
## Handoff And Result Contract
Use concise native messages and relevant file references; avoid whole-document copies. This contract defines meaning, not syntax/parser/schema.
|Assignment|Include|
|---|---|
|Identity/owner|Distinct task, responsible worker, goal, completion condition|
|Authority|Confirmed actions, exclusions, edit ownership, further-delegation permission|
|Context|Relevant YAIML/source paths and available revisions/hashes; direction, constraints, uncertainty|
|Method|Available skill or bounded procedure; disclose missing capabilities|
|Dependencies/limits|Prerequisites, worker/time/spend limits, retries, stop/decision conditions|
|Evidence|Independently grounded acceptance criteria and appropriate checks|

|Result|Include|
|---|---|
|Status|Completed, partial, blocked, failed, or cancelled; explicit remaining work|
|Outcome|Inspected/changed files, results, proposed memory corrections|
|Evidence|Sources, executed checks/outcomes, revision/environment, unrun checks|
|Uncertainty|Disagreements, limitations, dependencies, lead/user decisions|
|Cost/cleanup|Available usage, remaining processes/workspaces, cancellation leftovers|

Retain task identity. Dispatch is not completion; plans are not execution; defined checks are not passes; agent agreement is not independent evidence.
## Coordinate The Work
1. **Orient/propose:** read core and relevant support; select local procedures or available skills. A skill is a method, not a worker; native discovery depends on the host. Establish benefit, scope, and confirmation before delegation.
2. **Bound:** choose the smallest useful team; give each task completion/stop conditions. Workers inherit authority/limits and cannot expand access, recruit, or start paid services outside confirmed scope.
3. **Assign:** use native handoffs; parallelize only independent tasks. Coordinate ownership or use authorized isolated workspaces for writers. Re-reading does not prevent simultaneous writes.
4. **Collect:** use native completion notices or bounded waits; preserve partial results/disagreements. No continuous polling or unapproved retries. Stop at limits and disclose unenforced boundaries.
5. **Verify/integrate:** the lead checks results against original requirements and current files, re-reads changed context, rejects stale patches, preserves independent edits, and follows branch/review authority. Keep disputed changes out of shared defaults.
6. **Maintain:** designate integration to synthesize verified state in SoT, boundaries in Architecture, procedures in the Maintainer Guide. Remove superseded/resolved items; never append transcripts or diaries.

For “audit these aspects, summarize alignment, then do the next ten SoT items,” establish approved goals, reconcile audit findings, then select actionable priorities in user order, considering dependencies, blockers, and confirmed scope. Report fewer than ten when necessary. Task count is not worker count; an audit alone does not authorize repairs.
## Cost, Cancellation, And Verification
Repeated context/coordination can increase tokens. Unclear benefit: use one agent. No delegation merely because this guide exists, manufactured tasks, repeated full-memory loads, or background maintenance. Services/automation require separate explicit scope.
Use enforceable host limits; disclose unknown cost/unenforceable limits before confirmation. Estimates cannot promise hard caps. On cancellation: stop dispatching, invoke supported cancellation, report unstopped tasks/remaining changes.
Compare a bounded trial with single-agent work. Check confirmation, decline/no-answer, changed scope, absent capabilities, context cost, cancellation, concurrent edits, and evidence behind completion. Record actual execution and untested cases; document review proves neither adherence, security, nor savings.
