# yaiml-audit

Read [Using YAIML](../../YAIML_GUIDE.md) for shared context, evidence, authority and retention rules; reuse it and current core memory if already loaded. Accept scope and optional perspectives from the request, for example `/yaiml-audit accessibility, maintainability`. Without named perspectives, review the project's stated goals, current evidence, priority risks and memory accuracy; do not invent professional certification or numerical scores. Establish accepted goals and relevant invariants before assessing current behavior.

Inspect representative evidence for the selected scope. Check stale claims, false certainty, dead procedures/paths, missing risks, duplicated doctrine, overgrowth, lost corrections and contradictions between memory, implementation and branches. Distinguish deliberate design from accidental behavior and branch state from deployment. Specialized perspectives change the questions and evidence sought, not the reviewer's authority.

Ground expected outcomes independently of candidate output. Inspect scripts before proportionate checks; no destructive, deployment, dependency-install or external-service operation solely to verify a claim. Source-defined checks are not executed results. Separate reports, evidence and hypotheses; unrelated passes, agent agreement or failure to reproduce do not resolve a concern.

Return findings ordered by consequence, with location, evidence/scope, recommended correction and uncertainty. Preserve human direction and unresolved disputes. Audit-only scope does not authorize implementation; explicit read-only scope makes no memory edits. Otherwise record material understanding through `yaiml-maintain`. In a combined audit-and-work request, pass findings to priority selection without silently replacing approved priorities.
