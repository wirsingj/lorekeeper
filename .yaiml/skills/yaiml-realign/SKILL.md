# yaiml-realign

Read [Using YAIML](../../YAIML_GUIDE.md) for shared context, evidence, authority and retention rules; reuse it and current core memory if already loaded. Identify the authorized new direction, superseded intent and affected scope. An explicit realignment request authorizes its stated work; reuse approval. Criticism or an exploratory idea alone does not establish a new design or permission for broad removal. Clarify only unresolved decisions needed for dependent changes while continuing independent authorized work.

Rewrite affected memory around the approved direction; revise relevant skills/procedures when the way of working changes. Coordinate broad reorganization, preserve unrelated edits and governed knowledge, and remove or rename misleading artifacts only within scope. Application changes require implementation scope. Preserve declared design separately from current transition state and deployment; surface contributor disagreements.

Verify that guidance, skills, prompts, templates and examples agree, that references resolve and that planned behavior remains labeled. Before authorized integration compare meaning against the actual target and common ancestor; a clean merge proves no semantic agreement. Recheck affected evidence after integration changes.

Maintain the current account instead of appending a realignment diary. Report approved direction, changed artifacts, preserved constraints, actual checks and remaining divergence.
