# Instructions For Agents

Use YAIML as LoreKeeper project memory, not as a replacement for task-specific instructions.

## YAIML Project Memory

The maintainer treats these projects as works in progress: latest working files, including uncommitted edits, are the current baseline. Preserve that work; branch names and older commits do not establish production state or permission for Git mutations.

Read and follow [.yaiml/YAIML_GUIDE.md](.yaiml/YAIML_GUIDE.md). Use the [skill catalog](.yaiml/skills/INDEX.md) or host metadata to select specialized methods, read selected bodies, and pass requested actions/counts/perspectives unchanged. Ordinary work maintains material understanding without a YAIML reminder. Init executes bootstrap immediately; routine startup uses local guidance without upstream polling or backlog execution. Native `.agents/skills/` entries route to canonical methods.

At startup/context refresh, consider coordination from available context. For a concrete benefit, read [.yaiml/YAIMLACP.md](.yaiml/YAIMLACP.md), explain scope, access, limits, cost and the single-agent alternative, and obtain affirmative confirmation before first use or changed scope/cost. Otherwise continue independently.

Before meaningful work, read [.yaiml/yaiml.yml](.yaiml/yaiml.yml) and its four core roles: State of the Table, Architecture, Maintainer Guide, and Changes. Read selected stable headers before bodies and pending change records before relying on snapshots.
Load supporting documents only when relevant to the task.
Reuse already-loaded context while current; refresh it after relevant changes.
Verify consequential claims against the repository.

Before finishing material work, update affected memory and its local revision/change record as the guide directs. Preserve human direction, evidence limits, unresolved conflicts, and governed records. Respect read-only scope and review authority; report pending updates when writing is unavailable. Leave unchanged memory alone.

Keep routine edits passage-scoped. Memory describes this checkout: distinguish proposed, implemented, merged, and deployed. Before authorized integration, reconcile meaning against the actual target and common ancestor, including after clean textual merges. Preserve independent contributions and route unresolved decisions to the existing reviewer.

Memory may become public. Exclude machine-specific paths, private account URLs, credentials, and personal detail. Use sanitized evidence references rather than copying sensitive material.

“Update YAIML”, “updated YAIML”, or “check new YAIML” means refresh local methods from the public YAIML `main`, resolved once per invocation, unless the user explicitly supplies another source or ref. “Clean up YAIML”, “compress YAIML”, or “prune SoT” means synthesize stale or repeated memory without losing current truth. See the [Maintainer Guide](docs/MAINTAINER_GUIDE.md) for LoreKeeper-specific source and maintenance notes.
